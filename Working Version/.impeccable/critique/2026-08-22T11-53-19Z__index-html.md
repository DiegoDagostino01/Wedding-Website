## What's Working

1. **Guest-first progressive enhancement.** Content is visible by default everywhere; animations only activate when JS + IntersectionObserver + motion preference all say yes. Headless renderers, background tabs, and no-JS visitors all see a complete, readable page. This is the gold standard.

2. **Custom botanical SVG system.** The vine with 38 hand-placed blooms (garden roses, daisies, craspedia billy-balls, delphinium, lilac scabiosa, tulips, leaf sprigs) is extraordinary. The flower palette is sampled from the real bouquet photo (Assets/Flower Inspiration.jpg). This is the opposite of AI-generic — it's bespoke botanical illustration in CSS/SVG.

3. **RSVP form completeness.** Guest picker with keyboard nav (ArrowUp/Down/Enter/Escape), dietary select dropdown, partner handling, decline-collapse, already-replied detection, sending spinner, success state with return link, and email fallback. This form is production-grade.

4. **Copy voice.** "A layer for later," "Kind to the lawns," "This is the one that catches people out" — the copy consistently sounds human, warm, and practical, not template-like.

## Priority Issues

### **[P1] DESIGN.md / code mismatch on typography**
**What**: DESIGN.md declares Dancing Script (hero) + Montserrat-only. The page loads Great Vibes (hero) and Noto Serif Display (all headings).
**Why it matters**: DESIGN.md is the team's contract. Anyone extending this page on a later pass will reach for the wrong fonts. The page relies on Noto Serif Display for visual identity — its absence from the spec is a documentation bug.
**Fix**: Update DESIGN.md typography to reflect Great Vibes → hero display and Noto Serif Display → headings. Or commit to the originally documented fonts (load Dancing Script and drop Noto Serif Display from headings).
**Suggested command**: `/impeccable document Index.html`

### **[P1] Orphan text in stage-3 journey card (line ~3242)**
**What**: `<span class="journey-stage-number">03</span>Iceland` — the word "Iceland" sits as a bare text node between the number span and the kicker span, visible as orphaned text in the card header.
**Why it matters**: This is a rendering bug. The word "Iceland" prints directly after "03" with no wrapping element, competing with the `<h3>Iceland</h3>` heading directly below it.
**Fix**: Remove the orphan text node so only the `<h3>` carries the destination name.
**Suggested command**: Direct fix — remove the literal "Iceland" string after `</span>`.

### **[P1] Broken RSVP mailto link**
**What**: `href="mailto:Diego.beth21@gmail.com?subject=Wedding%20RSVP%20change"` in the `alreadyRepliedNote` has the subject corrupted to `VP%20change` (the "RS" is clipped).
**Why it matters**: Guests who need to change their RSVP will send an email with a garbled subject line, making it hard for the couple to triage.
**Fix**: Restore `subject=Wedding%20RSVP%20change` in the mailto href.
**Suggested command**: Direct fix.

### **[P2] Spring easing violates explicit design guidance**
**What**: `--ease-spring: cubic-bezier(0.34, 1.56, 0.64, 1)` produces bounce/overshoot. DESIGN.md says "Ease out with exponential curves (ease-out-quart/quint/expo). No bounce, no elastic."
**Why it matters**: The bounce easing reads as playful/cartoonish on what should be refined botanical motion. The spring curve is used on the countdown hover, CTA buttons, and journey marker transitions — all high-visibility interactions.
**Fix**: Replace `--ease-spring` with `cubic-bezier(0.16, 1, 0.3, 1)` (ease-out-expo) or the existing `--ease`. The countdown hover's upward translate already provides tactile feedback; the overshoot adds nothing.
**Suggested command**: `/impeccable animate` — adjust easing curves.

### **[P2] DESIGN.md radius and color tokens don't reflect the page**
**What**: DESIGN.md radius scale is {xs:3px, sm:4px, md:6px} but the page uses a full spectrum (2px → 999px). Colors like `--warm`, `--warm-deep`, `#C25B6E` (error), `#0b3550` (storymap dark), `#e7192c` (map pin), `#D98368` (blush) are all undocumented but well-used.
**Why it matters**: The page's actual design system is richer than DESIGN.md describes. Running `/impeccable document` would close this gap.
**Suggested command**: `/impeccable document Index.html`

### **[P3] Layout property transitions on nav**
**What**: `transition: padding` on nav and `transition: width` on nav-link underlines cause reflow on every scroll-triggered state change.
**Why it matters**: On weaker devices or during heavy scroll, these layout animations can jank. The nav-scrolled state is triggered by `scrollY > 40`, which fires continuously during scroll.
**Fix**: Move nav padding to a transform (e.g., `transform: scaleY()`) or remove the transition entirely — the state change is subtle enough to work without animation.
**Suggested command**: Direct fix.

## Persona Red Flags

### Jordan (First-Timer / Guest)
A guest visiting the site for the first time on mobile:
- **The journey map loads Leaflet JS (~40KB gzipped)** on mobile where the stage height is `clamp(210px, 33vh, 300px)` — a tiny viewport for a satellite map. The map is beautiful but on a phone it's mostly decorative.
- **The countdown timer shows seconds ticking** permanently. This is technically accurate but creates a sense of urgency/scarcity that could read as mildly stressful rather than anticipatory for an event ~8 months away.
- **No visible contact method at page bottom.** If a guest has a question not covered in the FAQ, they'd need to scroll back to the RSVP section to find the Diego.beth21@gmail.com address. A footer contact line would close this loop.

### Sam (Accessibility-Dependent)
- **The skip-to-content link works well.** The `.skip-link` is properly focusable.
- **The gallery lightbox is good**: Esc closes it, close button auto-focuses. But the gallery collage items use `role="button"` without `aria-expanded` or `aria-haspopup="dialog"` — a screen-reader user won't know a dialog will open.
- **Decorative elements are well-marked**: `aria-hidden="true"` on paper-grain, garden-light, petal-field, vine, sheen, scrim, frame, scroll-cue — this is done correctly.
- **The Leaflet map** has no aria-label on the container itself (the `#journeyLeafletMap` div has `aria-label` but Leaflet replaces its content). The map's interactive markers need `tabindex` and `role` attributes.

### Casey (Distracted Mobile)
- **Stay sort button** toggles between "Closest to the venue first" and presumably alphabetical. This works but the `aria-pressed` state updates on click — good.
- **Journey planner** requires typing a town or postcode. On mobile, the keyboard pushes the viewport up, and the "Plot my route" button can end up below the fold. Consider a sticky submit within the form container.
- **Gallery carousel** on mobile uses swipe/scroll-snap, but the prev/next buttons hide below 700px. On mobile, users must swipe horizontally — which works but isn't obvious without visual cues.

## Minor Observations

- The invitation veil (first-load "letter unfold" animation) is delightful. `html.invite` gate ensures it only plays when JS + motion are available. After the animation completes, the veil elements remain in the DOM indefinitely — they occupy `position:fixed` layers at z-index 300 with `pointer-events:none`, which is harmless but untidy.
- The two `<style>` blocks at lines ~12-2660 and ~2666-2746 split the CSS. The second block ("Aesthetic refinement pass") overrides rules from the first. Merging or at least commenting the split would help maintainability.
- The `.vine` component has its bloom animation driven by JS (scroll listener) rather than CSS scroll-timeline. The comment explains this is due to a Chromium bug with position:fixed scroll-timeline elements. Consider adding a note about which Chromium version the bug applies to, so a future maintainer knows when to switch to CSS.
- Gallery-wall collage and gallery-track carousel are two parallel presentation systems for the same photos. The carousel (`.gallery-track`) appears unused — there's no matching HTML in the body. This is dead CSS code.
- The `save-the-date.png` background pattern uses `background-attachment: fixed` on the body, which can cause performance issues on iOS Safari (the "rubber-band" scroll effect). Consider `background-attachment: scroll` for iOS or a media-query gate.
